# Amazon 运营工作台 · fnOS Docker

深蓝导航、白色表格的亚马逊运营工作台，集成赛狐 MCP。Node.js 24，无第三方运行依赖。

## 一条命令部署

在飞牛开启 Docker，SSH 进入你希望保存项目的共享目录，执行：

```sh
curl -fsSL https://raw.githubusercontent.com/canmingwei27-star/Amazon-work-web/main/install.sh | sh
```

脚本下载本仓库到当前目录的 `amazon-work-web`，生成网站 admin 登录密码，尝试拉取 GHCR 镜像；镜像不可用时自动从源码构建。记下终端显示的登录密码。首次构建或拉取需要 NAS 可访问 GitHub、GHCR 或 Docker Hub。

打开 `http://100.66.1.3:3080`，使用生成的账号登录，进入 **接口设置**，输入赛狐 `X-MCP-Key` → 保存 → 测试连接 → 一键拉取运营数据。不要在 GitHub、Issue 或聊天中填写密钥。

也可以下载仓库后在飞牛 Docker 项目管理中选择 `compose.yaml`：先复制 `.env.example` 为 `.env` 并填写网站登录账号。MCP 密钥留空，通过网页保存即可。

## 页面与功能

| 页面 | 功能与来源 |
|---|---|
| 今日总览 | 赛狐销售、利润、费用；工作区风险与到期任务；按已保存统计区间展示销售对比 |
| 销售异常 | 3/7/14日负毛利商品、周期覆盖提示、任务跟进 |
| 商品经营 | 主图缩略图；同步产品分析：销售额、销量、Sessions、转化率、广告花费、归因销售额、库存；搜索、CSV、SKU 关联详情 |
| 广告优化 | 官方 SP 活动汇总报告读取、ACOS >25% 提醒、有花费无销售提醒；另有小时诊断 |
| 搜索词明细 | 搜索词报告下载、CSV 导入/导出、点击、订单、花费、归因销售额、ACOS、记录来源与归因窗口 |
| 广告调整记录 | 判断依据、处理动作、负责人、执行日期、复查日期和结果，不自动修改亚马逊广告 |
| 关键词与竞品 | 词类、排名升降、使用位置、相关性、竞品观察、待验证假设；手动/CSV 维护 |
| Listing 与素材 | 当前问题、改版动作、负责人、交付、复查、版本记录、素材链接和文件上传 |
| 评价问题归类 | 反馈主题、提及次数、处理方向，关联改版任务 |
| 库存与补货 | 可售/预留/在途分开；可售天数 vs 补货周期；负责人、货件、预计到仓；可同步真实库存 |
| 在途货件 | 同步赛狐货件状态；运营补充 SKU、数量、预计到仓；保存原始记录供核对 |
| 运营日历 | 按月展示任务截止、复查与预计到仓 |
| 任务与复盘 | 四状态看板、负责人、依据、动作、截止、复查、结果；周复盘记录有效动作与下周优先 |
| 接口设置 | 手动保存/清除密钥、测试连接、一键拉取运营数据 |

所有工作区记录支持增删改、搜索、CSV 和 JSON 备份恢复。详情按 SKU 展示关联记录；编辑保留最近 30 个版本，商品同步保留最近 60 个版本。素材上传单文件最多 2MB，工作区备份最多 24MB，包含已上传素材，**不包含密钥**。导入 CSV 时，先导出本模块 CSV 查看表头模板；支持英文字段名及本模块中文表头，不猜测外部广告报表的指标含义。

## 数据口径

- ACOS = 同口径广告花费 / 广告归因销售额；严格大于 25% 异常，等于 25% 不标异常。有花费无销售单独关注，缺失值不补零。
- SP 小时报告为 7 天归因，按本次返回小时的基础金额汇总重算 ACOS，不平均比率。报告完整性和小时所在时区未知；每次最多扫描前 20 个活动，未读取和失败项不计正常。
- 真实产品分析以接口返回的 ASIN 分组记录保存，保留 SKU 列表。多 SKU 行不擅自拆分金额，需运营核对。不同币种不直接相加。
- 可售天数 = 可售库存 / 查询期间日均销量，小于人工维护的补货周期提醒。库存为当前快照，不作为查询日期当时的历史库存。在途不计入当前可售。
- 关键词搜索量、排名与竞品观察目前使用手动/CSV 数据；不声称赛狐提供未验证的排名追踪。素材、负责人、预计到仓与任务由用户维护。
- 销售对比展示实际保存的统计区间；没有历史记录时不生成虚构日趋势。周期长短可能不同，比较前应使用等长区间。
- 搜索词下载任务创建是有副作用的请求，只在用户点击确认后执行；不确定失败不能直接重放，先查询列表核对。
- 网站内提醒和页面每 5 分钟刷新仅在页面打开时运行，没有微信/邮件或浏览器关闭后的推送。

## 保存、更新与回滚

`workspace-data` 卷挂载到 `/app/data`，保存工作区、AES-256-GCM 加密密钥和解密主密钥。保护数据卷访问权限。密钥从不回显到浏览器或写入 GitHub；网页密钥优先于可选环境变量，清除会禁用网页密钥。

```sh
# 项目目录中更新镜像
sh deploy.sh
# 查看状态与日志
 docker compose ps
 docker compose logs --tail=100 dashboard
```

更新镜像保留数据卷。**不要执行 `docker compose down -v`**，它会删除数据卷。先在页面导出工作区备份。若需要回滚镜像，可将 compose 的 `latest` 改成已发布的提交 SHA 标签。密钥恢复需完整保留数据卷中的 `settings.enc` 和 `master.key`，工作区 JSON 备份不含这两个文件，也不含 users.json。恢复账号需同时保留 users.json。

仓库 push main 后，GitHub Actions 运行测试并构建 amd64/arm64 镜像到 `ghcr.io/canmingwei27-star/amazon-work-web`。镜像包可能需要仓库所有者设置公开可见性；若匿名拉取失败，部署脚本自动源码构建，无需输入 GitHub Token。

## 开发与验证

```sh
node --test
node --env-file-if-exists=.env server.mjs
```

覆盖 MCP 会话、SSE、分页、ACOS 边界、密钥加密恢复、产品字段与工作区持久化。健康检查只确认网站可用，不代表赛狐授权成功。已通过 Codex 连接核对产品分析真实字段；独立 Docker 的密钥联调需在网页输入密钥后完成。当前开发机器没有 Docker，构建由 GitHub Actions 验证，飞牛实际运行需现场确认。

接口：`https://api-mcp.sellfox.com/mcp`，请求头 `X-MCP-Key`。兼容直接业务工具及 `sf_describe/sf_execute` 网关；契约不匹配会报错，不自动猜参数。网站是单一共享工作区。管理员管理账号及密钥，运营成员共享业务数据。账号不开放公众注册，只有首次未初始化时可创建首位管理员；公开访问前请先完成初始化。通过公网访问时使用 HTTPS。

参考：[GitHub 官方 Docker 发布文档](https://docs.github.com/en/actions/tutorials/publish-packages/publish-docker-images)。
